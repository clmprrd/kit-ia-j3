À lire avant de commencer

Cette page suppose que vous êtes à l'aise avec un terminal. Rien ici n'est nécessaire pour la journée : c'est ce qu'il faut si vous voulez déployer pour une équipe plutôt que sur votre seul poste. Toutes les commandes viennent des documentations officielles, vérifiées le 9 septembre 2026.

Docker · la voie propre en entreprise

Pourquoi Docker plutôt qu'une installation directe

Le conteneur isole complètement Ollama du système : aucune dépendance qui traîne, aucun conflit de version Python ou CUDA. Et le volume rend le déploiement reproductible à l'identique sur n'importe quel poste ou serveur : vous redéployez la même pile en une commande, au lieu de refaire une installation manuelle poste par poste.

Ollama en conteneur
docker run -d -v ollama:/root/.ollama -p 11434:11434 --name ollama ollama/ollama
Avec accélération GPU NVIDIA (NVIDIA Container Toolkit requis)
docker run -d --gpus=all -v ollama:/root/.ollama -p 11434:11434 --name ollama ollama/ollama
Lancer un modèle dans le conteneur déjà démarré
docker exec -it ollama ollama run llama3
Ce que fait le volume

-v ollama:/root/.ollama stocke les modèles téléchargés en dehors du conteneur. Sans lui, vous re-téléchargez plusieurs gigaoctets à chaque redémarrage.

Open WebUI · l'interface d'équipe

C'est ce qu'on recommande à la place de PrivateGPT

Une interface web complète par-dessus Ollama : conversations, documents, comptes utilisateurs.

Installation officielle, connectée à un Ollama déjà installé
docker run -d -p 3000:8080 \
  --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data \
  -e WEBUI_SECRET_KEY=votre-cle-secrete \
  --name open-webui --restart always \
  ghcr.io/open-webui/open-webui:main

Interface sur http://localhost:3000. Le flag --add-host suffit à ce qu'Open WebUI trouve tout seul l'Ollama de votre machine.

Alternative sans Docker
pip install open-webui
open-webui serve

Interroger vos propres documents

Menu latéral, puis Workspace → Knowledge → Create. Vous donnez un nom, vous téléversez vos fichiers (PDF, texte, code). Ils sont découpés et indexés automatiquement.

Ensuite, dans n'importe quelle conversation, le symbole # fait apparaître un menu pour attacher un fichier ou toute la base. Vous pouvez aussi rattacher la base à un modèle en permanence dans Workspace → Models → Edit.

Plusieurs utilisateurs, et c'est le point qui compte

RôleCe qu'il peut faire
AdminLe tout premier compte créé. Gère les utilisateurs et les permissions.
UserUtilise l'outil selon les droits de son groupe.
PendingEn attente de validation par un admin. C'est la file d'entrée.
Pourquoi c'est le critère décisif pour une équipe

Les permissions se gèrent par groupes depuis Admin Panel → Users → Groups. C'est ce qui rend Open WebUI déployable dans une structure, là où un outil mono-poste s'arrête à votre bureau.

AnythingLLM · le RAG sans configuration

Deux façons de l'installer

Application de bureau : un installeur classique Mac, Windows ou Linux. Pas de terminal, pas de Docker.

Version Docker
docker pull mintplexlabs/anythingllm:master

export STORAGE_LOCATION="/var/lib/anythingllm"
mkdir -p $STORAGE_LOCATION
touch "$STORAGE_LOCATION/.env"

docker run -d -p 3001:3001 --cap-add SYS_ADMIN \
  -v ${STORAGE_LOCATION}:/app/server/storage \
  -v ${STORAGE_LOCATION}/.env:/app/server/.env \
  -e STORAGE_DIR="/app/server/storage" \
  mintplexlabs/anythingllm:master

Interface sur http://localhost:3001.

La différence nette avec Open WebUI

AnythingLLM embarque une base vectorielle et un pipeline documentaire dès le départ : vous glissez un document dans un espace de travail, il est indexé immédiatement, sans rien configurer. Chez Open WebUI, le RAG est une fonctionnalité additionnelle du chat.

Il gère aussi des espaces de travail séparés par projet, chacun avec ses propres documents. Attention : la gestion des accès par espace n'existe qu'en version Docker, pas en version bureau.

L'API · brancher vos propres scripts

Trois façons d'appeler votre modèle local

Génération simple
curl http://localhost:11434/api/generate -d '{
  "model": "llama3.2",
  "prompt": "Pourquoi le ciel est-il bleu ?"
}'
Conversation, avec historique
curl http://localhost:11434/api/chat -d '{
  "model": "llama3.2",
  "messages": [{"role": "user", "content": "Pourquoi le ciel est-il bleu ?"}]
}'
L'endpoint compatible OpenAI · celui qui intéresse votre DSI
curl -X POST http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "mistral:7b",
    "messages": [{"role": "user", "content": "Dis bonjour."}]
  }'
Ce que ça permet concrètement

Ollama expose /v1/chat/completions, exactement comme OpenAI. Une application existante bascule sur votre modèle local en changeant la seule base_url vers http://localhost:11434/v1/. Le code métier ne change pas.

En Python, avec la bibliothèque officielle
pip install ollama

from ollama import chat
response = chat(
    model='gemma3',
    messages=[{'role': 'user', 'content': 'Pourquoi le ciel est-il bleu ?'}]
)
print(response['message']['content'])
Interroger vos documents, en local

Le chemin le plus court en 2026

AnythingLLM en Docker. Vous glissez un document dans un espace de travail, il est découpé et indexé automatiquement. Aucune base vectorielle à installer séparément.

Si vous avez déjà Open WebUI en place, inutile d'ajouter un outil : sa section Workspace → Knowledge couvre le même besoin.

Le modèle qui transforme vos textes en vecteurs

Le modèle d'embedding à prendre, 274 Mo
ollama pull nomic-embed-text
À quoi sert un modèle d'embedding, en une phrase

Il transforme chaque morceau de vos documents en une suite de nombres, pour que le système retrouve les passages qui ressemblent à votre question. C'est ce qui permet de chercher par le sens et pas par les mots exacts.

Le rappel qui vaut pour tout ce qui est sur cette page

Un traitement local reste un traitement de données personnelles. Aucune de ces installations ne vous dispense d'une base légale, de la minimisation, de la sécurité ni de l'information des personnes. Et rien de tout ceci ne se met en production sans l'accord de votre responsable de la sécurité des systèmes d'information.
